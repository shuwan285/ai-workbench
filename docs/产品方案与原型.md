### 0.4 三个设计要点说明

**① 第 3 项的连带收益。** 加了概念层之后，「知识点被哪些项目使用」变成一次 `ProjectKnowledge` 查询，
改名、改分类、补充默认资源都不影响历史关联，而且知识模板库（第二阶段）天然成立 ——
模板就是一组 `conceptId` 的集合，不是一堆要重新关联的文本副本。

**② 第 4 项的落地方式。** 浏览器拿不到本地文件系统路径（`<input type="file">` 出于安全只给 File 对象，
不含真实路径），所以「浏览器原生选择器」这条路走不通。但你是对的 —— 不该为此暴露目录接口。
采用**后端唤起系统对话框**：

| 平台 | 实现 | 过滤器 |
| --- | --- | --- |
| Windows | `powershell -STA` + `System.Windows.Forms.OpenFileDialog` | `*.exe;*.lnk` |
| macOS | `osascript -e 'choose file'` | 由系统按扩展名过滤 |
| Linux | `zenity --file-selection` | 同上 |

后端只做两件事：弹出对话框、把用户选中的路径回传。**没有任何"传入路径 → 列出内容"的能力**，
前端也无法用这个接口探测磁盘。对话框会强制 `TopMost`，避免被浏览器窗口挡住。
注意：对话框开在**运行 Node 服务的那台机器**上 —— 个人本地使用没问题，这也是不选云端的原因之一。

**实施时的调整**：过滤器原本写的是 `*.exe;*.lnk;*.bat;*.cmd`，实测后去掉了 `.bat` 和 `.cmd`。
原因见 2.1 的启动逻辑 —— 批处理文件必须经 `cmd.exe /c` 执行，而 `cmd.exe` 会对命令行做**二次解析**，
路径里的 `&` `|` 会被当成语法。与其写容易漏的转义，不如直接拒绝并引导用户改用「命令行」类型
（那里是 `spawn(command, args, { shell: false })`，没有这个问题）。

**③ 第 7 项的预置数据。** ChatGPT / Claude 默认 `type: 'web'`，指向 `https://chatgpt.com` 和 `https://claude.ai`。
首页两个按钮开箱即用，不会出现死按钮。想换成桌面客户端 → Agent 管理页改类型为「桌面应用」并填路径，
此时才会出现「未配置路径」状态和配置引导。

## 1. 数据模型（最终版）

### 1.1 Project

```js
Project {
  id: string                      // 'p_' + base36 时间戳 + 随机后缀
  name: string
  description: string
  category: string                // 预设 '课程作业' | '编程开发' | '论文与研究'，设置页可增删
  status: 'idea' | 'planning' | 'active' | 'paused' | 'done'
  priority: 'high' | 'medium' | 'low'
  progress: number                // 0-100，由 progressMode 决定是计算值还是 manualProgress
  progressMode: 'auto' | 'manual'
  manualProgress: number          // 手动模式的值；切回 auto 时保留不清零
  coverColor: string              // '#5B8DEF'，取自 8 色预设板
  startDate: string               // 'YYYY-MM-DD'
  dueDate: string | null
  nextAction: string
  constraints: string[]           // ★ 新增。一行一条；Prompt 的 {{constraints}}
  tags: string[]
  relatedLinks: { label: string, url: string }[]
  notes: string
  archived: boolean               // ★ 归档的唯一真相
  createdAt: string               // ISO 8601
  updatedAt: string
}
```

### 1.2 Task（未改动）

```js
Task {
  id: string
  projectId: string
  title: string
  description: string
  status: 'todo' | 'doing' | 'review' | 'done'
  priority: 'high' | 'medium' | 'low'
  dueDate: string | null
  estimatedHours: number | null
  completedAt: string | null
  order: number                   // 同列内排序，步长 1000，便于插入
  createdAt: string
  updatedAt: string
}
```

### 1.3 知识点：概念层 + 项目关联层（★ 结构性调整）

拆成两张表。**「知识点是什么」和「这个项目为什么需要它」是两件事**，之前混在一条记录里，
导致知识库无法跨项目复用、改名即断链。

```js
KnowledgeConcept {                // 概念层：跨项目复用的通用知识
  id: string
  name: string                    // 通用名称，如「理解曝光三要素」
  category: string                // '编程' | '设计' | '研究' | 'AI工具' | '写作' | '其他'
  description: string             // 该概念本身的说明（与具体项目无关）
  defaultResources: { label: string, url: string }[]   // 默认学习资源
  createdAt: string
  updatedAt: string
}

ProjectKnowledge {                // 关联层：某个概念在某个项目里的状态
  id: string
  conceptId: string               // → KnowledgeConcept.id
  projectId: string               // → Project.id
  reasonNeeded: string            // 这个项目为什么需要它（项目专属）
  status: 'notStarted' | 'learning' | 'mastered'
  estimatedMinutes: number | null // 在本项目预计投入时长（项目专属）
  resourceLinks: { label: string, url: string }[]   // 项目专属补充资源
  blocksProject: boolean          // 是否阻塞当前任务
  notes: string                   // 项目备注
  createdAt: string
  updatedAt: string
}
```

**关系**：`Project 1—N ProjectKnowledge N—1 KnowledgeConcept`。
「知识点被哪些项目使用」= 按 `conceptId` 查 `ProjectKnowledge` 再连 `Project`，**不依赖名称**。

**去重规则**：新建概念时，先按 `name` 归一化（去空格 + 转小写 + 去全角）查重。
命中则提示「已有知识点『理解曝光三要素』，是否直接关联？」——
默认关联已有，也允许强制新建（用于确实要区分的近义概念）。名称只用于**创建时的提示**，不承担关联职责。

**删除语义**：
- 删除 `ProjectKnowledge`（项目里移除该知识点）→ 概念保留在知识库
- **删除 `KnowledgeConcept`：有引用时禁止删除。** 知识点是长期积累的资产，误删成本高，
  因此不提供任何「一次从所有项目移除并删除」的快捷路径。分两种情况：
  - **引用数 > 0** → 删除按钮置灰不可点。模态框列出引用它的项目数量与名称（含各自掌握状态），
    唯一操作是「前往管理关联」→ 打开关联管理面板，逐个「从该项目移除」。
    每移除一个引用数减一，减到 0 后删除按钮才恢复可用。
  - **引用数 = 0** → 正常二次确认后删除。
- 删除项目 → 级联删除其 `ProjectKnowledge`，**概念本身保留**（即使因此变成 0 引用也不自动清理）

### 1.6 存储（实施后调整为磁盘落盘）

> 第一轮澄清时定的是「浏览器 localStorage」，实施完成后按新的优先级改成了磁盘文件。
> 原因是接了真实模型之后知识点会变成长期积累的资产，只挂在会被清掉的 localStorage 上风险太大。

**磁盘是正式副本，浏览器只是镜像。**

```
~/.ai-workbench/
├─ data.json           当前数据（含 revision 与 savedAt）
├─ data.backup.json    上一版，每次写入滚动
├─ data.corrupt.json   仅在解析失败时出现
└─ config.json         自定义可信命令
```

目录用 `os.homedir()` 推导，代码里不出现任何硬编码盘符，可用 `AIWB_DATA_DIR` 覆盖。
（「在 UI 里选数据目录」属于第二阶段。）

**写入链**：改动 → 0.6s 防抖 → 写浏览器镜像 → `PUT /api/data` → 服务端
「写临时文件 → 复制旧版为 backup → rename 原子替换」。

**并发保护**：state 带单调递增的 `revision`。服务端发现磁盘版本更高就返回 409，
前端停止写入并提示「从磁盘重新加载」，两个标签页同时开着不会互相覆盖。

**启动核对**（`src/store/recovery.js`，纯函数）：

| 情况 | 处理 |
| --- | --- |
| 本地服务没起来 | 用镜像跑，顶部橙色横幅常驻提示未落盘 |
| 磁盘无文件 + 镜像有数据 | 自动迁移并提示 |
| 镜像有数据 + 磁盘在但浏览器被清 | 静默从磁盘恢复 |
| 镜像 revision > 磁盘 | 弹窗二选一（恢复本地 / 用磁盘），未决期间挂起写入 |
| 磁盘 revision > 镜像 | 用磁盘 |
| 版本一致 | 用磁盘 |
| 磁盘文件解析失败 | 原文件另存为 `data.corrupt.json`，**绝不覆盖**，退回镜像并提示 |

导入仍校验 `schemaVersion`，未知版本拒绝并提示，不静默丢字段。
导入格式兼容第一版方案里的扁平 `knowledgeItems`（自动升格为 concept + relation）。

## 2. 核心机制实现

### 2.1 Agent 打开：三种类型，一条安全底线

**统一入口** `POST /api/agent/launch`。

**web**（不需要后端）
```
window.open(url, '_blank', 'noopener,noreferrer')
```
被浏览器拦截弹窗时 → Toast 提示「浏览器拦截了新标签页，请允许本站弹窗」。

**desktop**
1. 路径为空 → `{ ok:false, code:'EMPTY_PATH' }`
2. `fs.existsSync` 为 false → `{ ok:false, code:'NOT_FOUND' }`
3. `spawn(path, [], { detached:true, stdio:'ignore', shell:false }).unref()`
   - Windows 的 `.lnk` 不能直接 spawn，交给 `spawn('explorer.exe', [path])`
   - Windows 的 `.bat` / `.cmd` → `{ ok:false, code:'BATCH_NOT_SUPPORTED' }`，
     引导用户改用「命令行」类型。原因：必须经 `cmd.exe`，而 `cmd.exe` 会二次解析命令行
   - macOS 走 `spawn('open', [path])`
   - Linux 先 `accessSync(path, X_OK)` 确认可执行，再直接 spawn

**command**
1. `command` 为空 → `{ ok:false, code:'EMPTY_COMMAND' }`
2. 命令不在允许列表 → `{ ok:false, code:'COMMAND_NOT_ALLOWED' }`
   - 默认项（`server/lib/commandWhitelist.js`）：
     `python` `python3` `node` `npm` `npx` `git` `code` `ollama` `jupyter` `conda` `pip`
     `claude` `cargo` `java` `R` `Rscript`
   - 这是**默认值，不是硬限制**。设置页 →「高级：自定义可信命令」可显式添加，带风险提示 + 二次确认。
   - 自定义项存**服务端** `~/.ai-workbench/config.json`，不存 localStorage、不由前端随请求下发。
3. 命令存在性：按 `PATH` + `PATHEXT` 解析，解析不出来 → `{ ok:false, code:'COMMAND_NOT_FOUND' }`
4. 参数或解析出的路径含 `& \| ^ < > % "` 或换行 → `{ ok:false, code:'ARG_UNSAFE' / 'PATH_UNSAFE' }`
5. `cmd.exe /c start "" <解析出的绝对路径> <args…>`（Windows）

**安全底线（三种类型共用）**

| 规则 | 做法 |
| --- | --- |
| 不用 shell | 不用 `exec`、不用 `execSync`；除命令行类型的 `start` 外全程 `shell: false` |
| 参数不拼接 | 桌面类型 `args` 以数组原样传给 `spawn`，路径里的 `&` `\|` `>` 不会被解释 |
| 命令行类型拒绝元字符 | 它必须经 `cmd.exe` 才能开出终端，绕不开二次解析，所以会改变含义的参数一律拒绝，不做转义 |
| 命令行类型先查 PATH | 经了 `cmd` 就收不到 `ENOENT`，启动前自己解析一遍，免得「命令没装」变成静默失败 |
| 命令白名单 | `command` 必须命中允许列表（默认项 + 用户显式添加的自定义项） |
| 白名单存服务端 | 存 `~/.ai-workbench/config.json`。若由前端随请求下发，白名单等于没有 |
| 路径不落盘 | 后端不持久化任何 Agent 路径，只做一次性校验和启动 |
| 只监听本地 | Express 绑 `127.0.0.1`，不绑 `0.0.0.0`，局域网访问不到 |

**接口边界（★ 此方案的安全前提）**

只绑 `127.0.0.1` 还不够 —— 浏览器里的**任意网页**同样能向 `http://127.0.0.1:5174` 发请求。
不设防的话，一个恶意页面就能调 `/api/agent/launch` 启动本地程序。三道防线：

1. **`Origin` 校验**：只接受 `http://localhost:5173` / `http://127.0.0.1:5173`，
   缺失或不匹配一律 403。浏览器发起的跨站请求必定带 `Origin`，这条挡住绝大多数场景。
2. **CORS 收紧**：`cors({ origin: [...] })` 明确列白名单，不用 `origin: true`。
3. **强制自定义请求头**：写接口要求 `X-AIWB: 1`，非简单请求触发预检，预检被上述 CORS 挡回。

成本近乎为零（前端加一个请求头），换来的是堵上「本机任意网页都能启动程序」这个洞。

**定性（第三轮补充）：这三层是浏览器跨站防护，不是身份认证。**

它们挡的是「别的网站偷偷调你的本地接口」，挡不住「本机上任意能发 HTTP 请求的程序」——
任何本地进程都能伪造 `Origin` 和请求头。当前架构下这不构成问题：前端由本地 Vite 提供，
服务只监听回环，使用者就是本机用户本人。

**但如果以后打包成桌面端、把本地 API 暴露给更多调用方，需要补一个服务端生成的随机 token**：

- 启动时生成，通过受控的启动流程下发
- 下发方式：注入到「由服务端提供的那份 HTML」里 —— 跨站页面读不到别的源的 DOM，
  所以这比放在前端能自由读取的公开配置里强
- **不要**把 token 写死在前端源码里，也**不要**放在随请求公开返回的配置接口里

**错误码 → 提示文案**（杜绝静默失败）

| code | 文案 | 附带操作 |
| --- | --- | --- |
| `EMPTY_PATH` | 还没配置「Claude」的程序路径 | 「去配置」 |
| `EMPTY_COMMAND` | 还没配置「本地脚本」的启动命令 | 「去配置」 |
| `NOT_FOUND` | 找不到程序：`C:\...\Claude.exe` | 「去配置」「复制路径」 |
| `COMMAND_NOT_ALLOWED` | 命令 `xxx` 不在白名单里 | 「查看白名单」 |
| `LAUNCH_FAILED` | 启动失败：<系统错误原文> | 「复制路径」 |

**「测试打开」** 走同一个接口，成功绿色 Toast，失败红色 Toast，文案同上。

### 2.2 文件选择器

`POST /api/agent/pick-path` → 唤起系统原生对话框 → `{ ok:true, path:'C:\...\Claude.exe' }`
用户取消 → `{ ok:false, code:'CANCELLED' }`（前端静默处理，不报错）。

仅回传用户主动选中的文件路径，**没有任何目录遍历能力**。

### 2.3 项目进度

```
progressMode === 'manual' → manualProgress
progressMode === 'auto'   → total === 0 ? 0 : round(done / total * 100)
```

切换开关在「任务与进度」Tab 顶部；切到 manual 时把当前计算值写入 `manualProgress` 作为起点，避免跳变。
进度条 300ms 过渡。总任务为 0 时显示「还没有任务」而非 0%。

### 2.4 阻塞知识点

```
关联表判定：projectKnowledge.some(k => k.blocksProject && k.status !== 'mastered')
```

三处呈现：
1. Dashboard 顶部琥珀横幅「⚠️ 3 个项目被知识点卡住」→ 展开 → 点击跳具体条目
2. 项目卡片右上角琥珀小圆点 + hover 提示「有 N 个阻塞知识点未掌握」
3. 项目详情顶部横幅，可关闭；关闭状态记在项目上，**下次该项目的知识点状态变化后重新出现**

### 2.5 截止日期分级

```
diff = ceil((due - today) / 86400000)
diff < 0   → 已逾期   红 + 左上角标
diff <= 3  → 紧急     红 + 加粗
diff <= 7  → 临近     琥珀
diff <= 30 → 正常     常规灰
diff > 30  → 不显示（保持界面干净）
```

### 2.6 Prompt 组装

模板原文不变，变量填充规则：

| 变量 | 来源 | 为空时 |
| --- | --- | --- |
| `{{projectName}}` | `project.name` | 必填，不会为空 |
| `{{category}}` | `project.category` | （待补充） |
| `{{description}}` | `project.description` | （待补充） |
| `{{projectStatus}}` | status 中文映射 | （待补充） |
| `{{progress}}` | 计算值 | 恒有值 |
| `{{nextAction}}` | `project.nextAction` | （待补充） |
| `{{taskList}}` | 未完成任务，按 doing→todo→review 排序<br>每条 `- [高] 排备选照片（截止 09-20，预计 2h）` | （暂无任务） |
| `{{knowledgeGaps}}` | `blocksProject` 优先、再按 status 排序<br>每条 `- 理解曝光三要素（未开始，预计 120 分钟）—— 阻塞` | （暂无） |
| `{{constraints}}` | `project.constraints.join('\n')` | （待补充） |

**不虚构**：不编造技能水平、不猜学校专业、不补未提供的日期。缺失一律显式写「（待补充）」，让 AI 自己追问。

复制用 `navigator.clipboard.writeText`，失败降级 `textarea + execCommand('copy')`。
「打开并复制」= 先写剪贴板 → 再调启动接口 → 启动失败也保留剪贴板内容并提示
「程序没打开，Prompt 已复制，可手动粘贴」。

### 2.7 数据安全

- 每次 dispatch 后 debounce 600ms：先写浏览器镜像，再推磁盘（见 1.6）。
  镜像写入失败（配额溢出）→ Toast 警告并引导导出；磁盘写入失败 → 改动仍留在镜像里，横幅常驻提示
- **删除项目**：模态框列出连带影响「将同时删除 12 个任务、5 个知识点关联、3 条资料；知识点本身保留在知识库」，
  需**手动输入项目名**才能点确认
- **删除概念**：列出引用它的项目名，确认后从各处移除
- 删除任务 / 关联：普通二次确认
- 导入：解析校验 → 预览摘要（N 项目 / M 任务 / K 概念）→ 选覆盖或合并 → 确认

## 7. 确认状态与实施记录

三轮裁决全部确认。本方案为编码依据；实施中偏离方案的地方记录如下。

**已偏离的地方**（均已在上文对应章节更新）：

1. **文件选择器过滤器去掉 `.bat` / `.cmd`**（见 2.1）。批处理必须经 cmd.exe 二次解析，
   与其写易漏的转义不如直接拒绝并引导改用命令行类型。
2. **存储从 localStorage 改为磁盘 JSON 文件**（见 1.6）。第四轮调整优先级时确定：
   接了真实模型之后知识点会成为长期资产，只挂在浏览器上风险太大。
   同时补了自动保存、JSON 导出和启动恢复检查。
3. **接口安全的定性写清楚了**（见 2.1 末）。三层防护是浏览器跨站防护，
   不是身份认证；桌面端分发需要补服务端生成的 token。
4. **真实模型接入已实施**（第五轮）。用 Anthropic SDK + 结构化输出，默认 `claude-opus-4-8`；
   key 只存服务端 `config.json`，接口只返回头尾几位；真实调用失败时退回模拟数据
   并在界面上明确标出。详见 `README.md` 的「安全设计 · 边界三」。
5. **端点地址不读环境变量**（实施中发现）。SDK 默认会读 `ANTHROPIC_BASE_URL` 和
   `ANTHROPIC_AUTH_TOKEN`，而这个应用很可能从「已经为别的工具配了代理」的 shell 里启动 ——
   实测中请求被悄悄发去了第三方端点，报错完全看不出原因。所以端点只认应用自己的配置，
   默认官方地址；凭据仍可用 `ANTHROPIC_API_KEY` 环境变量（换 key 不改变请求去向）。
   这个坑是本地工具常见的，写在这里备查。

6. **命令行类型改为在新终端里运行**（见 2.1）。原方案写的是 `spawn(command, args,
   { detached:true, shell:false })`，实测这套参数给 GUI 程序用是对的，给交互式 CLI 用是错的 ——
   起的进程既没有控制台也没有输入，`claude` 起来即退，`python -i` 变成看不见也敲不进去的
   僵尸进程，而两种情况界面都报「已启动」。现改为经 `cmd.exe /c start` 开真终端。
   代价是 cmd 会二次解析命令行，所以**「参数原样直传」这条不变量在命令行类型上不再成立**，
   改为拒绝会改变含义的参数（理由与拒绝 `.bat` / `.cmd` 相同：宁可拒绝，不写容易漏的转义）。
   同时补了启动前的 `PATH` 预检，因为经了 `cmd` 之后拿不到「命令没装」的错误。
   只在 Windows 上实现和验证；非 Windows 维持原行为，见 `README.md` 第 3 条。

7. **新增「执行路线」，并设为项目详情的默认 Tab**（见 2.x）。原方案里任务和知识点是两条
   平行的列表，各在各自 Tab 里，中间没有连线 —— 结果是打开项目看到的是「一堆任务」和
   「一堆知识点」，回答不了「这一步该先补什么」。现在由 `ProjectKnowledge.stepTaskId`
   建立起关联（指向路线上的某一步，单个 id，可为 `null`），执行路线按任务顺序把两者串起来。
   默认 Tab 从「概览」改成它，因为「现在该做哪一步」是打开项目最常问的问题。

   **`stepTaskId` 落在知识点那一侧，而且是单个 id** —— 一个知识点只跟一步走。这一点
   实施中改过一次：第一版放在任务侧、用数组（多对多），试用后发现每个任务看到的候选
   都是全量、看不出归属，于是改成现在这样，理由和取舍记在开发笔记里（不随仓库分发）的
   「中途改过设计」一节。

   **归属由 AI 来排，不是让用户排。** 这一点实施中又改过一次：最初把录入放在用户手上，
   但**这个工具的存在前提就是「用户不知道自己缺什么」** —— 让他去判断「哪个知识点属于哪一步」
   是把最该 AI 做的事推回给用户。现在两条路径：生成知识点时一并给出归属（主路径），
   以及对已有知识点单跑一次「让 AI 排到各步」（补漏，结果先预览再应用）。
   手动下拉降级为修正手段。

   **AI 看不出归属的不硬塞**：留「未安排」，报「跟项目无关」的标出来由用户决定。
   模型给的 id 一律拿真实任务 id 复核，编出来的作废。

   **路线要能照着做，还得能回答「做得完吗」。** 这一点也改过一次：早先的路线只是个
   *进度视图*（有哪些步骤、什么状态、挂了哪些知识点），不是能照着动手的计划。
   现在每步都带「要做什么」（`Task.description`）和「算完成」（`Task.doneWhen`），
   每个知识点带「为什么需要它」（`ProjectKnowledge.reasonNeeded`）；没写「要做什么」的
   步骤会明确提示。

   **任务侧也交给 AI**（原先任务侧完全没有 AI，步骤只能靠自己想）：
   `POST /api/ai/plan-project` 把项目拆成步骤（每步带说明和完成标准）；
   `POST /api/ai/review-plan` 对着项目说明复核「照这个做完能不能交付、缺什么」，
   缺的能一键补进去。

   **完整度应用自己保证不了** —— 只能让模型对着项目说明复核。所以模拟数据这里只能做
   结构检查（哪一步没写全），**查不出「项目还缺哪一步」**，这一点会写在结论里，
   免得「没报问题」被当成「计划是完整的」。

   **接第三方端点：`ai.compatMode`。** 原方案只有官方端点一种假设。实测发现多数 Anthropic
   兼容端点会默默忽略 `output_config`、回散文，导致解析失败且报错看不出原因。兼容模式下改成
   把 schema 写进提示词 + 配对扫描挖 JSON，验 key 也改用最小对话（第三方没有 Models API）。
   **代价是失去硬保证**，官方端点不要开。详见 `README.md`。
   顺带把来源标签从写死的「由 Claude 生成」改成显示**实际模型名**。

   **知识点改为「以步骤为纲」生成。** 原设计是「完成这个项目需要补哪些基础知识」，
   产出的是话题（「摄影构图」「照片后期」）。但使用者卡住的地方是**做法**
   （「怎么把逆光下的人脸拍清楚」）。现在生成会对着每一步的「要做什么」问
   「不会什么就动不了手」，并明确要求具体到能照着做。条数上限从 8 放到 20 ——
   按步骤生成十几条很正常，卡在 8 条会把后面几步要的东西直接裁掉。

   **「不能过少」是硬指标 + 服务端校验**。原设计只在提示词里写「别硬凑也别硬压」，
   模型完全可以给少。现在：拆解必须覆盖「搞清楚交付物 → 准备 → 主体 → 验证 → 交付」
   且不少于 6 步；知识点要求**每一步都必须有**。生成后由 `planShortfall` /
   `knowledgeShortfall` 校验，不达标就把「缺什么」告诉模型**自动重来一次**；
   重来还不够就如实报出来，不假装完整。条数上限放到 45 —— 卡在 30 会把最后几步的东西
