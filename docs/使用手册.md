## 一、它解决什么问题

你手上同时有好几个项目在推进，每个都卡在某个地方 —— 而卡住你的往往不是「没时间」，
是**「这一步要用的东西我还没学过」**。

通常的工具只帮你记「要做什么」，不帮你回答「我缺什么、先补哪个、补到什么程度算够」。
这个工具就是冲这个来的：

| 它做 | 它不做 |
| --- | --- |
| 把项目拆成**能照着做**的几步，每步写清「要做什么」「算完成」 | 替你完成任务 |
| 对着每一步问「不会什么就动不了手」，列出要补的知识点 | 替你决定学不学 |
| 把知识点按顺序挂到步骤上，标出哪条正在**挡路** | 给你排课表 |
| 检查这份计划**做完能不能交付**，指出缺哪一步 | 保证计划完整（做不到，见下） |

两个前提：

1. **它是本地工具。** 跑在你自己电脑上，数据存成你磁盘上的一个 JSON 文件。
   没有账号、没有云同步、不联网（除非你主动接了 AI）。
2. **不接 AI 也能用。** 拆解项目、生成知识点这些会退回本地模拟数据，功能都在，
   只是结果比较泛。接了 AI 质量会明显不一样。

## 二、装起来

**不需要懂编程。** 六步，大约五分钟。这一节把每一步拆开讲清楚，包括可能卡住的地方。

### 1. 把代码下下来

在仓库页面上方找到绿色的 **`Code`** 按钮 → 点开 → **`Download ZIP`**。

会下载一个 `ai-workbench-main.zip`。解压到一个你找得到的地方，比如 `D:\ai-workbench`。

**要下载哪些内容？全部。** 解压出来会是一堆文件和文件夹：

```
ai-workbench-main/
├─ src/            界面（你看到的所有页面）
├─ server/         本地服务（读写文件、启动程序、调 AI）
├─ scripts/        测试脚本
├─ docs/           文档，看不看都行
├─ package.json    依赖清单 —— 这个不能少
└─ ...
```

不用挑，**缺任何一个都跑不起来**，整个文件夹留着就行。真正干活的是 `src/` 和 `server/`。

> 路径里带中文或空格**一般没问题**（实测可以），但个别 Windows 环境 + 命令行工具的组合
> 会在中文路径上出岔子。想省事就放在纯英文路径下。

（会用 git 的话：`git clone https://github.com/shuwan285/ai-workbench.git`）

### 2. 装 Node.js

这个工具是用 Node 写的，先得有它。

打开 **https://nodejs.org/**，下载写着 **LTS** 的那个（不要下 Current），双击，一路「下一步」。
默认选项就行，不用改。

> ⚠️ **装完必须新开一个命令行窗口。** 已经开着的窗口认不出新装的命令 ——
> 这是最常见的「我明明装了为什么还说找不到」的原因。

### 3. 打开命令行

进到解压出来的那个文件夹，**在窗口顶部的地址栏里**把里面的路径清空，输入 `cmd`，回车。

会弹出一个黑底白字的窗口，光标前面显示的就是那个文件夹的路径。

### 4. 装依赖（只有第一次需要）

在黑窗口里输入：

```
npm install
```

回车。它会下载运行需要的那些库，等十几秒到一分钟（看网速）。跑完回到可以继续输入的状态。

> 如果结尾出现 `npm warn allow-scripts ...` 之类的黄色警告，**可以忽略**，不影响使用。

### 5. 启动

```
npm run dev
```

回车。看到这样的输出就是成功了（时间、路径会不一样）：

```
[web]   VITE v5.4.21  ready in 1051 ms
[web]
[web]   ➜  Local:   http://localhost:5173/
[server]   AI 创作项目工作台 · 本地服务
[server]   接口   http://127.0.0.1:5174/api
[server]   数据   C:\Users\<你>\.ai-workbench\data.json
[server]   配置   C:\Users\<你>\.ai-workbench
```

**这个窗口不要关** —— 它就是服务本身。

### 6. 打开界面

浏览器访问 **http://localhost:5173**

第一次打开是空的。点「**或导入示例项目体验一下**」会放三个示例项目进去，先随便点点看。

### 以后每次要用

进文件夹 → 地址栏输 `cmd` → `npm run dev` → 打开 http://localhost:5173。

**不用再 `npm install`。** 用完按 **Ctrl + C** 关掉，或者直接关窗口。

### 关于那两个进程

`npm run dev` 会同时起两个，**别只起一个**：

| 进程 | 端口 | 干什么 |
| --- | --- | --- |
| 前端（Vite） | 5173 | 你看到的界面 |
| 本地服务（Express） | 5174 | 读写磁盘、启动程序、调 AI |

两个都只绑 `127.0.0.1`，同一局域网里的其他机器访问不到。

> **改了后端代码要重启。** Vite 的热更新只管前端，`server/` 下面的改动不重启不生效。

### 装不上的时候

| 现象 | 原因和办法 |
| --- | --- |
| `'npm' 不是内部或外部命令` | Node 没装成功，或者装完没重开命令行窗口。关掉黑窗口重新开一个 |
| `Error: Port 5173 is already in use`<br>`EADDRINUSE: address already in use 127.0.0.1:5174` | 上次的没关干净。把之前那个黑窗口关掉；找不到就重启电脑 |
| `npm install` 一直不动 | 网络问题。换国内镜像再重跑：<br>`npm config set registry https://registry.npmmirror.com` |
| 提示 Node 版本太低 | 需要 18 以上，去 nodejs.org 下 LTS 重装 |
| 浏览器打不开 localhost:5173 | 回头看那个黑窗口，它多半报了错。窗口关了服务也就停了 |

**还是不行**，把黑窗口里的报错原文贴出来问。

### 端口被占用了（想自己查的话）

改完代码没生效，多半是这个 —— `concurrently` 的子进程不会跟着父进程一起被杀掉。

```powershell
netstat -ano | findstr :5174
netstat -ano | findstr :5173
taskkill /PID <查到的PID> /F
```

**两个端口都要看**，5173 是前端，5174 是接口。在 Git Bash 里可以：

```bash
netstat -ano | grep -E ":5174|:5173" | grep LISTENING
```

## 三、先看五分钟

第一次打开是空的。**点空状态里的「或导入示例项目体验一下」**，会往里面放三个示例项目，
配好了任务、知识点、Agent 和 Prompt 模板。

导入后随便点开一个 —— 你会直接落在**「执行路线」**页，那是这个工具最核心的一屏。
它的结构是这样（下面是版式示意，实际内容取决于你的项目）：

```
③ 这一步要做什么                            [进行中] ← 你在这
   要做什么：这一步具体怎么动手。
   算完成：做到什么程度算完。
   ─────────────────────────────────────
   📚 这一步要补的知识点       未开始  [先补这个]
        为什么这一步需要它，不补会卡在哪。
```

竖着读下来就是「按顺序做哪几步、每一步要先补什么」。看够了可以到
**设置 → 数据 → 清空所有数据** 重来（清之前它会让你手打「清空」确认）。

## 四、接入 AI

**不接也能用。** 四条 AI 路径在没配 key 时都会退回本地模拟数据，而且会在界面上
**明说这次是模拟的** —— 不会让你以为模型真的生成了那些内容。

想换成真实模型：**设置 → AI 生成**，三步。

### 第一步：选供应商

| 选项 | 什么时候选 |
| --- | --- |
| **Anthropic 官方** | 你有 Anthropic 的 key。能力最强，结构化输出有硬保证 |
| **DeepSeek** | 想用便宜的第三方。会自动帮你打开兼容模式 |
| **其他兼容端点** | 任何兼容 Anthropic 协议的端点，地址自己填 |

选一下只是把下面的端点地址、模型、兼容模式**填进表单**，填完照样能改。
**存下来的是那份配置本身，不是「你选了哪家」** —— 所以以后要换代理，直接改端点地址就行。

### 第二步：贴 key

API key 输入框下面有「**去 XXX 拿 key →**」，直接跳到对应平台的申请页。

### 第三步：测试连接 → 保存

先测试再保存，测不过就不用存。

**如果之前配过 key**，输入框留空表示不改动；填新的会直接覆盖。

### 高级选项（一般不用动）

展开「**高级：端点地址、模型、兼容模式**」：

| 字段 | 说明 |
| --- | --- |
| **模型** | 可以填任意模型 ID，下拉里是当前供应商的常见选项 |
| **端点地址** | 留空 = 官方端点。走代理或自建网关才填这里 |
| **兼容模式** | 端点不认识 Anthropic 的结构化输出时打开。**官方端点不要开** |

官方端点能保证返回的一定是符合 schema 的 JSON。很多第三方兼容端点会忽略结构化输出要求，
直接回一段散文，解析失败。兼容模式的做法是把格式要求写进提示词、去掉官方专有参数、
从返回里把 JSON 提取出来。

兼容模式没有硬保证。模型不听话时还是会失败，失败会退回模拟数据并说明原因。
连试两次都是模拟数据才算问题。

### key 存在哪

- 存在 `~/.ai-workbench/config.json` 的 `ai.apiKey` 字段里，**只由本地服务读**
- 界面上只显示「头几位…后几位」，完整 key 不出后端进程
- 也可以用 `ANTHROPIC_API_KEY` 环境变量代替（**配置文件里的优先**）
- 想彻底清掉：设置页点「**移除 key**」

端点地址不读环境变量。很多人为别的工具在 shell 里设了 `ANTHROPIC_BASE_URL`，应用跟着走的话
请求会发去第三方端点，报错看不出原因。端点只认应用自己的配置，默认是官方地址。

## 五、从零做一个项目

这一节是主线。假设你要做一个「个人博客网站」。

### 1. 建项目

首页点「**+ 新建项目**」。**「项目描述」这一栏别省** —— 后面 AI 的所有产出都靠它：

> 用 Vite + Express 做一个个人博客：能写文章、带评论，最后部署到自己的云服务器上。

其他字段（类别、优先级、截止日期、标签、工具与限制）都可以之后补。
**「工具与限制」会原样填进项目 Prompt**，写「只能用免费工具」「不熟悉数学推导」这类
真实约束，AI 才知道你的实际条件。

### 2. 让 AI 把项目拆成步骤

打开项目 →「**任务与进度**」→ 点「**让 AI 拆解项目**」。

它读你的项目描述，拆出若干步骤，**每步带「要做什么」和「算完成」**。结果先预览，
可以逐条改标题和说明，勾选要的再加进去。

> **为什么要有这一步。** 「不知道这步该做什么」和「不知道要学什么」是同一个困境。
> 只解决一半的话，你还是会卡住。

没写项目描述就点，它会提醒你：`先写两句项目说明，拆出来的步骤才贴题。`

### 3. 生成知识点

切到「**知识点清单**」→「**✨ AI 生成建议**」。

生成出来的不是「前端开发」这种话题，而是**贴着具体步骤的、能动手的做法**。
两者差别大概是这样：

| 话题式（没用的） | 以步骤为纲（有用的） |
| --- | --- |
| 前端开发 | `react-markdown` 渲染文章正文时要过滤 HTML，否则访客在评论里贴一段脚本就能偷走登录态 |
| 部署上线 | Nginx 把 `/api` 反代给 Express、其余走静态文件；证书用 certbot 申请，还要配自动续期 |

每条都标着「**在哪一步之前补**」，可以直接改。AI 看不出归属的**不会硬塞** ——
留成「未安排」，判断跟项目无关的还会在旁边标出来，由你决定留还是删。

结果可以逐条勾选，不会直接写进去。

### 4. 看执行路线

回到「**执行路线**」（打开项目默认就是它）。任务和知识点在这一页串成了一条线，
每步显示「要做什么」「算完成」，每个知识点显示「为什么需要」。

这一页最上面有一排汇总：「N 步」「已完成 N」「有 N 步卡在知识点上」「有 N 步没安排知识点」……

### 5. 检查这份计划能不能做完

执行路线页点「**检查能不能做完**」。

它拿你的项目描述和已有计划对照，回答「照这个做完能不能交付」，并列出缺口，
每一条都标着类型：

| 标签 | 意思 |
| --- | --- |
| **缺一步** | 少了某个环节，比如功能都做完了但没安排部署和上线后验证 |
| **缺知识点** | 某一步缺了对应要补的东西 |
| **这步说不清** | 步骤的「要做什么」或「算完成」太空 |

缺的可以**一键补进去**。

> ⚠️ **这条要读清楚**：完整性这件事**应用自己保证不了**，只能让模型对着项目描述复核一遍。
> 用本地模拟数据时只能查出「哪一步没写全」，**查不出「项目还缺哪一步」** ——
> 这一点会写在结论里。**别把「没报问题」当成「计划是完整的」。**

### 6. 做起来

- 任务在「**任务与进度**」页，四列看板（待开始 / 进行中 / 待复查 / 已完成），**直接拖**
- 做完一个把状态拖到「已完成」，项目进度自动涨
- 知识点学完了在「知识点清单」里把状态改成「已掌握」
- 卡住的时候回「执行路线」看 —— 它会用「**⚠ 知识点没跟上**」标出哪一步被挡着

**「阻塞」是什么**：某个知识点没掌握就没法往下做，在知识点上勾「这个知识点没掌握会阻塞
当前任务」。首页和项目页会专门提醒你有几个知识点在挡路。

## 六、逐个页面讲清楚

侧边栏五项：**工作台 / 项目 / 知识库 / Agents / 设置**。

### 工作台（首页）

一屏看完「现在该干什么」：

| 区块 | 内容 |
| --- | --- |
| **快速打开 Agent** | 你固定到首页的 Agent，点一下就打开。没配置会显示「未配置 · 去设置」 |
| **总览** | 四张卡：进行中项目 / 3 天内截止 / 本周完成任务 / 待学习知识点 |
| **知识点阻塞提醒** | 有几个知识点在挡着哪个项目，点进去直接到那一页 |
| **最近项目** | 最多 3 个，带「下一步行动」 |
| **今日待办** | 今天到期的任务 |
| **学习提醒** | 正在学的知识点、预计还要多少小时、其中几个在阻塞项目 |

没有项目时整页是空状态，三个按钮：`新建项目` / `或导入示例项目体验一下` / `接入 AI`
（第三个只在没接 AI 且你把引导横幅关掉之后出现）。

### 项目中心

- **搜索**项目名、描述、标签
- **筛选**：类别 / 状态 / 优先级 / 截止（已逾期、3 天内、7 天内、30 天内）/ 显示已归档
- **视图**：卡片 / 列表
- **排序**：最近更新 / 创建时间 / 截止日期 / 优先级 / 名称

筛选条件会同步到网址栏，**刷新和后退都不会丢**。

每个项目右上角「⋯」里有：编辑、**复制一份**、归档/取消归档、删除。

> **删除项目要手打项目名确认。** 会同时删掉它的任务和知识点关联，
> 但**知识点本身保留在知识库**，其他项目不受影响。

### 项目详情

六个 Tab，打开项目默认落在**执行路线**：

| Tab | 干什么 |
| --- | --- |
| **执行路线** | 任务 × 知识点的合并视图，见上一节。带「检查能不能做完」 |
| **概览** | 项目简介、当前阶段、下一步行动、工具与限制、备注、日期、关联链接 |
| **任务与进度** | 四列看板 / 列表，带「让 AI 拆解项目」 |
| **知识点清单** | 这个项目要补的东西，带 AI 生成、模板库、让 AI 排到各步 |
| **Agent 工作区** | 项目专属 Prompt、一键打开 Agent、Prompt 模板 |
| **项目资料** | 文档 / 素材 / 参考资料 / 复盘记录四组 |

**概览页值得说两句**：

- **「下一步行动」只写一件事**，具体到能立刻动手。首页会把它顶到最显眼的位置
- **进度**默认按任务完成数自动算，也可以切成「手动调整」拖滑块
- **「工具与限制」**一行一条，会原样填进项目 Prompt

**任务与进度页**：看板可以直接拖卡片。任务可以只有标题，但填了「要做什么」和「算完成」
之后，执行路线才能真正当工作计划用。没有任务时可以点快捷模板起个头：
`文献综述` / `写代码 → 调试 → 出图` / `实验报告`。

所有任务完成后会问你要不要把项目标成已完成。

### 知识库

**跨项目复用的知识点都在这里。** 在项目里加的知识点会自动汇总过来。

关键设计是**拆成两层**：

| 层 | 属于谁 | 存什么 |
| --- | --- | --- |
| **概念** | 所有项目共用 | 名称、领域、通用说明、默认学习资源 |
| **关联** | 某个具体项目 | 为什么这个项目需要它、掌握状态、预计时长、是否阻塞、项目备注 |

所以「HTTP 缓存机制」这个概念只有一个，两个项目都关联它、各自的掌握进度互不干扰。
**改名不会断开关联。**

有项目在引用时不能删概念，要先逐个解除关联，减到零才放行。知识点是长期积累的东西，
误删代价高。

添加知识点时会先搜知识库里有没有同名的，有就直接关联，不重复创建。

### Agents

三种类型：

| 类型 | 怎么打开 | 要填什么 |
| --- | --- | --- |
| **🌐 网页** | 新标签页 | 网址 |
| **🖥️ 桌面应用** | 本地服务启动 `.exe` / `.lnk` | 程序路径（可以点「浏览…」用系统选择器挑） |
| **⌨️ 命令行** | 在**新终端窗口**里运行 | 命令 + 参数（一行一个） |

**命令行类型能跑交互式程序**（`claude`、`python -i`），因为它是开一个真终端窗口，
不是后台静默执行。

几个限制：

- 命令必须命中允许列表（默认 16 个常见开发工具）。要加新的去
  **设置 → 高级：自定义可信命令**
- 参数里不能出现 `& | ^ < > % "` 和换行。命令行类型必须经 `cmd.exe` 启动，
  它会二次解析命令行，这些字符会改变含义。不做转义，直接拒绝
- `.bat` / `.cmd` 请改用「命令行」类型配置

**打开失败不会静默。** 它会告诉你具体原因和下一步，比如：

| 情况 | 提示 |
| --- | --- |
| 命令没装 | `系统里找不到「uv」这个命令。确认它装好了，并且能直接在终端里跑起来。` |
| 命令不在白名单 | `命令「uv」不在允许列表里。可以在设置页把它加进可信命令。` |
| 路径写错 | `找不到程序：D:\Apps\X.exe。检查一下路径是否正确。` |

每个 Agent 可以**固定到首页**（点「固定到首页」），首页就会出现快捷入口。

### 设置

五个分区：

**AI 生成** —— 见第四节。

**外观** —— 浅色 / 深色 / 跟随系统。侧边栏底部也有个主题切换按钮。

**项目类别** —— 新建项目时能选的类别。已经用在项目上的不能删。

**高级：自定义可信命令** —— 命令行类型 Agent 的允许列表。加自定义命令时会弹窗
说明风险，确认后才加。

**数据** —— 保存状态、数据文件信息、导入导出、清空。见下一节。

## 七、数据在哪，怎么备份

### 存在哪

```
~/.ai-workbench/                     Windows 上是 C:\Users\<你>\.ai-workbench\
├─ data.json            当前数据
├─ data.backup.json     上一版（每次写入自动滚动）
├─ data.corrupt.json    只有文件解析失败时才会出现
└─ config.json          自定义可信命令 + AI 凭据
```

想换位置：设环境变量 `AIWB_DATA_DIR`；配置文件同理走 `AIWB_CONFIG_DIR`。

### 怎么存的

**磁盘上的 JSON 文件是正式副本，浏览器里的只是镜像。**

- 每次改动 **0.6 秒后**自动写入磁盘
- 浏览器里同时留一份镜像 —— 万一没来得及写磁盘（比如页面被强关），下次打开会提示你恢复
- 写入前会比对版本号。发现磁盘上的版本更新（比如另一个标签页写过），**会停止写入并报警**，
  而不是默默覆盖

### 备份 / 迁移

| 做法 | 在哪 |
| --- | --- |
| **导出 JSON** | 设置 → 数据 → `导出 JSON`，或者侧边栏底部的「导出数据」 |
| **导入** | 设置 → 数据 → `选择文件`。会先显示文件里有什么，再选**合并**还是**覆盖** |
| **直接拷文件** | 把 `~/.ai-workbench/data.json` 复制走就行 |
| **打开目录** | 设置 → 数据 → `打开数据目录` |

**导入时会给你看清楚再决定**：

> 「合并」会保留现有数据，只补充 id 不重复的条目；「覆盖」会清掉现在全部内容。

## 八、出问题怎么办

### 顶部出现琥珀色横幅「本地服务没启动」

改动目前只存在浏览器里。**重新跑起 `npm run dev` 之后会自动补写到磁盘**，不用刷新页面。

### 顶部出现红色横幅「磁盘上的数据比这里的更新，写入已停止」

另一个标签页写过东西。点「去处理 →」看提示，页面上会给你处理冲突的入口。

> **已知限制**：两个标签页共享同一份浏览器存储。标签页 B 遇到冲突后**不处理直接刷新**，
> B 会静默回到磁盘版本，那笔改动会丢。要根治得给版本号加客户端标识，暂时记为已知限制。

### 打开时弹「发现浏览器里有未写入磁盘的改动」

上次可能没来得及保存就关掉了页面。选「用磁盘上的版本」或「恢复浏览器的改动」。

这个弹窗不能跳过，按 Esc 或点外面都关不掉，必须选一个。不然容易在没看清的情况下
丢掉一边的数据。

### AI 生成的结果看起来像套话

八成是**在用本地模拟数据**。看生成结果上方的来源标记：

- `由 deepseek-chat 生成` —— 真的
- `本地模拟数据` —— 假的，去设置页接 AI

### 接了 AI 但偶尔失败

兼容模式**没有硬保证**，模型不听话时会退回模拟数据并说明原因。
**连试两次都是模拟数据才算问题。**

### 命令行类型的 Agent 打不开

按提示走。最常见的两种：

- `命令「xxx」不在允许列表里` → 去设置页加进可信命令
- `系统里找不到「xxx」这个命令` → 它没装，或者装了但不在 `PATH` 里

### 忘了 AI key，或者想清掉

设置 → AI 生成 →「**移除 key**」，回到本地模拟数据。

### 跑测试

```bash
npm run test          # 领域逻辑（289 项）
npm run test:ui       # 界面渲染（68 项）
npm run test:conflict # 双标签页并发（25 项，自带服务实例）
npm run test:launch   # 命令行启动规则（30 项，不起真进程）
npm run test:all      # 四套一起，412 项
```

这些是给改代码的人用的。你只是使用者的话不需要跑。
