# AI 创作项目工作台

把 AI Agent、项目进度、要补的知识点和一个项目专属 Prompt 放在一个页面里的本地工具。
给同时推进好几个 AI 创作项目、但常常卡在「这个我还没学过」的人用。

---

## 怎么跑起来

**不需要懂编程。** 照着下面六步做，大约五分钟。之后每次用只要两步（第五步和第六步）。

### 1. 把代码下下来

页面上方有个绿色的 **`Code`** 按钮，点开 → **`Download ZIP`**。

会下载一个 `ai-workbench-main.zip`，把它解压到随便一个地方，比如 `D:\ai-workbench`。

> 解压出来的文件夹里有很多东西，**这些全都要**，不用挑。真正干活的是 `src/`（界面）
> 和 `server/`（本地服务），但缺了任何一个文件都跑不起来，所以整个留着就行。

（会用 git 的话，`git clone https://github.com/shuwan285/ai-workbench.git` 效果一样。）

### 2. 装 Node.js

打开 **https://nodejs.org/**，下载写着 **LTS** 的那个版本，双击，一路「下一步」。

这个工具是用 Node 写的，装它才能在你电脑上跑起来。装完**必须新开一个命令行窗口**，
否则它认不出来。

### 3. 打开命令行

进到刚才解压出来的文件夹，**在窗口顶部的地址栏里**把路径清空，输入 `cmd`，回车。

会弹出一个黑底白字的窗口，光标前面显示的路径就是那个文件夹。

### 4. 装依赖（只有第一次需要）

在黑窗口里输入这一行，回车：

```
npm install
```

它会下一堆东西，等十几秒到一分钟（看网速）。跑完会回到可以继续输入的状态。

### 5. 启动

```
npm run dev
```

看到下面这样的输出就是成功了（右边的时间、路径会不一样）：

```
[web]   VITE v5.4.21  ready in 1051 ms
[web]
[web]   ➜  Local:   http://localhost:5173/
[server]   AI 创作项目工作台 · 本地服务
[server]   接口   http://127.0.0.1:5174/api
[server]   数据   C:\Users\<你>\.ai-workbench\data.json
```

**这个黑窗口不要关** —— 它就是服务本身，关掉服务就停了。

### 6. 打开界面

浏览器访问 **http://localhost:5173**

第一次打开是空的。点页面中间的「**或导入示例项目体验一下**」，
会放三个示例项目进去，可以随便点点看。

### 以后每次要用

进到那个文件夹 → 地址栏输 `cmd` 回车 → `npm run dev` → 浏览器打开 http://localhost:5173 。

**不用再跑 `npm install`**，那是第一次才需要的。

用完在窗口里按 **Ctrl + C**，或者直接把窗口关掉。

### 卡住了看这里

| 现象 | 怎么办 |
| --- | --- |
| `'npm' 不是内部或外部命令` | Node 没装成功，或者装完没重开命令行窗口。关掉黑窗口重新开一个 |
| `Error: Port 5173 is already in use`<br>`EADDRINUSE: address already in use 127.0.0.1:5174` | 上次的没关干净，端口还占着。把之前那个黑窗口关掉；找不到就把电脑重启一次 |
| 浏览器打不开 localhost:5173 | 回头看那个黑窗口，它多半报了错。窗口关掉的话服务也就停了 |
| `npm install` 一直不动 | 网络问题。可以换成国内镜像再重跑：`npm config set registry https://registry.npmmirror.com` |
| 提示 Node 版本太低 | 需要 18 以上。去 nodejs.org 下 LTS 版重装 |

**还是不行的话**，把黑窗口里的报错原文贴出来问，一般都能查出来。

**下一步**：接上 AI（不接也能用，只是生成的内容比较泛）—— 见下面「接入 AI」。
再往下就是怎么用这个工具，看 [`docs/使用手册.md`](docs/使用手册.md)。

## 接入 AI

**不接也能用。** 拆解项目、生成知识点、复核完整度、把知识点排到各步 —— 这四条路径在没配
key 的时候都会退回本地模拟数据，并且在界面上**明说这次是模拟的**，不会让你以为模型真的生成了。

想换成真实模型，打开界面上的「设置 → AI 生成」，三步：

1. **选供应商** —— Anthropic 官方、DeepSeek，或者「其他兼容端点」自己填地址
2. **贴 key** —— 页面上有「去拿 key →」直接跳到对应的申请页
3. **测试连接 → 保存** —— 先测再存，测不过就不用存

选供应商只是把端点地址、模型、兼容模式**填进表单**，填完照样能改；存下来的是那份配置本身，
不是「你选了哪家」。所以以后要换代理，改端点地址就行。

| | |
| --- | --- |
| 支持什么 | 任何兼容 Anthropic Messages 协议**且支持结构化输出**的端点。不认 `output_config` 的（多数第三方）需要打开「兼容模式」，此时改成把返回格式写进提示词、自己解析 JSON —— 能用，但没有硬保证 |
| 兼容模式代价 | 模型不听话时会解析失败，此时会退回模拟数据并说明原因。连试两次都是模拟数据才算问题 |
| key 存哪 | `~/.ai-workbench/config.json` 的 `ai.apiKey`。**只由本地服务读，接口往外只给「头几位…后几位」**，完整 key 不出进程 |
| 换把 key | 设置页直接填新的覆盖，或者用 `ANTHROPIC_API_KEY` 环境变量代替（配置文件里的优先） |
| 费用 | 按量计，单价看你选的端点。这个应用不会替你决定用哪个型号 |

## 接下来（给要改代码的人）

需要 Node 18 以上（开发时用的是 24）。数据文件默认落在 `~/.ai-workbench/data.json`
（Windows 上是 `C:\Users\<你>\.ai-workbench\data.json`），想换位置就设环境变量 `AIWB_DATA_DIR`；
配置文件（含 AI 凭据）同理走 `AIWB_CONFIG_DIR`。代码里没有任何硬编码盘符。

`npm run dev` 会同时起两个进程：前端 Vite（`127.0.0.1:5173`）和本地服务 Express
（`127.0.0.1:5174`，只绑回环地址）。

## 已实现

**工作台** — 问候语、Agent 快捷入口、四个统计卡、阻塞提醒、最近项目、今日待办、学习提醒。
三个空状态都有明确引导。

**项目管理** — 增删改查、归档、复制、搜索、按类别/状态/优先级/截止日期筛选、卡片与列表双视图、
五种排序。筛选条件同步到 URL，刷新和后退都不会丢。

**任务与进度** — 四列看板，原生 HTML5 拖拽，也可切换列表视图。进度默认按任务完成数自动算，
可以切手动模式拖滑块，切换时用当前值打底不会跳变。所有任务完成时会提示标记项目为已完成。

**执行路线** — 打开项目默认看到的那一页。把「按顺序做哪几步」和「每一步要补什么知识」
合到一条线上：

```
③ 挑出三十张并试着排序                      [进行中] ← 你在这
   要做什么：从素材里挑出三十张，按场景分组，看能不能串成一条线。
   算完成：能说出这组照片想讲什么，且每张都对得上
   ─────────────────────────────────────
   📚 用一组照片讲一个主题     未开始  [先补这个]
        挑片和排序全靠它，没主题就只能凭感觉凑够十二张。
```

没写「要做什么」的步骤会有提示。

任务和知识点是两张表，中间的连线是 `projectKnowledge.stepTaskId`，指向路线上的某一步，
可以是 `null`（未安排）。一个知识点只跟一步走，由数据结构保证（单个 id，不是数组）。

归属由模型决定，不让人来排：

- **生成知识点时一并给出**（主路径）。模型本来就在读项目描述，顺带把任务列表也给它。
- **「让 AI 排到各步」**（补漏）。对已有知识点单独跑一次，先预览再应用。

模型看不出归属的留成「未安排」，判断跟项目无关的会标出来。模型返回的 id 一律拿真实任务 id
复核，对不上的作废。

「知识点清单」里每行也有「服务哪一步」下拉，用于手动修正和筛「未安排」。删除步骤时，
挂在它上面的知识点会回到「未安排」。

**任务侧也交给模型。** 「任务与进度」页有「让 AI 拆解项目」，读项目说明拆出步骤，每步带
「要做什么」和「算完成」，先预览再应用。执行路线页有「检查能不能做完」，拿项目说明和
已有计划对照，列出缺口，可一键补进去。

完整度只能靠模型对着项目说明复核，应用本身保证不了。复核结果会标出来源：本地模拟数据
只能查「哪一步没写全」，查不出「项目还缺哪一步」。

**知识点** — 拆成概念层和项目关联层两张表：

- 概念（名称、领域、通用说明、默认资源）跨项目复用
- 关联（为什么这个项目需要它、掌握状态、预计时长、是否阻塞、项目备注）属于具体项目

改名不会断开关联。有项目在引用时禁止删除概念，只能逐个解除关联，减到零才放行。
添加知识点时会先搜一下知识库里有没有同名的，有就直接关联。支持 AI 生成建议和四个内置知识模板包。

**AI 生成知识点按步骤走**：项目拆出步骤之后，对着每一步的「要做什么」问「不会什么就
动不了手」，不按项目主题泛泛地想。

| 以项目为纲 | 以步骤为纲 |
| --- | --- |
| 摄影构图 | 逆光拍人时把测光点放在脸上，不然背景一亮人就成剪影 |
| 照片后期 | 一组照片调色时先统一白平衡再动饱和度，反过来容易越调越花 |
| 排版与配色 | 横竖构图混着放时要留统一的页边，不然整组看起来是散的 |

**条数下限靠校验，不靠提示词里的要求**，两道：

1. 提示词里写硬指标：拆解要覆盖「交付物 → 准备 → 主体 → 验证 → 整理交付」，
   不少于 6 步；生成的每一步都必须有知识点。
2. 服务端校验，不达标就带着「缺什么」重来一次（`planShortfall` / `knowledgeShortfall`）。

重来过还是不够的话会说明。条数上限是 45，卡在 30 会把最后几步要的东西裁掉，
反而被校验判成那几步没知识点。

**AI 生成建议**默认走本地模拟数据（按关键词匹配），在设置页接上模型后换成真实的。
官方端点用结构化输出（`output_config.format`）约束返回格式。调用失败会退回模拟数据
并在界面上标出来。

**第三方端点需要打开「兼容模式」。** 很多兼容端点会忽略 `output_config` 并返回散文，
`JSON.parse` 直接失败。兼容模式下把格式要求写进提示词、去掉 `thinking` 和 `output_config`、
从返回里配对扫描提取 JSON（能处理代码块包裹和前后寒暄）。验 key 也不走 Models API，
改用一次最小对话。

兼容模式没有硬保证：官方端点能保证返回符合 schema 的 JSON，兼容模式只能靠提示词约束和
宽松解析，模型不听话时会失败并退回模拟数据。官方端点不要开。

来源标签显示实际模型名（如「由 deepseek-chat 生成」）。

**Agent** — 三种类型：网页（新标签页打开）、桌面应用（后端启动 .exe/.lnk）、
命令行（白名单内的命令，在新终端窗口里运行）。桌面路径可以用系统文件选择器挑。

命令行类型开真终端，所以 `claude`、`python -i` 这类交互式程序能正常用。代价是启动要经
`cmd.exe` 的 `start`，它会二次解析命令行，所以参数里不能出现 `& | ^ < > % "` 和换行，
出现就拒绝，不做转义。启动前先在 `PATH` 里确认命令存在，因为经了 `cmd` 之后拿不到
「命令没装」的错误。

**Prompt** — 按项目名称、类型、目标、阶段、进度、下一步、任务、知识缺口、工具与限制组装。
缺失字段写「（待补充）」。可复制、可一键打开 Agent 并复制、可存成模板，模板支持 `{{变量}}`。

**数据** — 落盘到本地 JSON，浏览器留一份镜像（见下一节）。支持导出 / 导入（导入前显示预览，
可选覆盖或合并）。删除项目需要手输项目名确认。

**其他** — 深色模式、窄屏抽屉侧边栏、键盘可达（焦点环、焦点陷阱、Esc 关闭）、
状态不只靠颜色。

## 数据保存在哪

**磁盘上的 JSON 文件是正式副本，浏览器里的 localStorage 只是镜像。**

```
~/.ai-workbench/
├─ data.json           当前数据
├─ data.backup.json    上一版，每次写入自动滚动
├─ data.corrupt.json   只有文件解析失败时才会出现
└─ config.json         自定义可信命令 + **AI 凭据的唯一落点**（ai.apiKey）
```

`config.json` 的 `ai.apiKey` 是整份配置里唯一敏感的东西。它只存在这个文件里，
只被服务端读，接口往外只给「头几位…后几位」。想把它挪出主目录，设环境变量 `AIWB_CONFIG_DIR`。

**写入流程**：任何改动 → 0.6 秒防抖 → 先写浏览器镜像 → 再 PUT 给本地服务 → 服务端
「写临时文件 → 备份旧版 → 原子改名」。所以断电或进程被杀都不会得到一个半截文件。

**为什么还要留浏览器镜像**：页面可能在你还没来得及写磁盘时就关了。镜像让改动不至于丢，
下次打开时由恢复检查兜住。

**启动时的核对**（`src/store/recovery.js`，纯函数，有单测覆盖全部分支）：

| 情况 | 处理 |
| --- | --- |
| 本地服务没起来 | 用镜像继续跑，顶部挂一条橙色提示，说明改动暂不落盘 |
| 磁盘还没有文件、镜像有数据 | 自动迁移，并提示「已把浏览器里的数据写入磁盘」 |
| 浏览器数据被清了、磁盘还在 | 静默从磁盘恢复 |
| 镜像版本 > 磁盘版本 | **弹窗问你**：恢复浏览器的改动，还是用磁盘版本 |
| 磁盘版本 > 镜像版本 | 用磁盘（多半是另一个标签页写过） |
| 版本一致 | 直接用磁盘 |
| 磁盘文件解析失败 | 原始内容另存为 `data.corrupt.json`（绝不覆盖），退回镜像并提示 |

**并发写入用的是基线比对，不是版本号比大小。**

每次改动 `revision` 加一，写入时客户端还要带上「这次改动是基于哪一版做的」（`baseRevision`）。
服务端发现基线和磁盘上的版本对不上就返回 409，前端停下写入并提示处理冲突。

为什么不能只比新版本号：两个标签页都停在第 5 版，各自改一次，算出来的新版本号**都是 6**，
`6 < 6` 不成立，后写的会把先写的静默覆盖掉 —— 典型的丢失更新。比对基线才拦得住
（「你基于第 5 版改，但磁盘已经到第 6 版了」）。

只有用户在恢复对话框里明确选了「用本地覆盖磁盘」时，才会带上 `force` 跳过这道校验。

设置页能看到数据文件路径、版本号、最后写入时间、文件大小和同步状态，
还有「立即保存」「从磁盘重新加载」「打开数据目录」三个按钮。

## 两点需要知道的

**1. 数据在磁盘上，但也建议偶尔导出。** 正式副本是 `~/.ai-workbench/data.json`，
清浏览器缓存不会丢。但整台机器重装或误删还是会没 —— 侧边栏底部有一级入口的「导出数据」。
清缓存之后重开，会自动从磁盘恢复，并提示你一句。

**2. 网页版 Agent 和桌面版是两种配置。** 预置的 ChatGPT / Claude 是网页版，点开就是新标签页。
想改成桌面客户端，去 Agent 管理页把类型改成「桌面应用」并填路径，之后才会出现「未配置路径」的提示。
批处理文件（.bat/.cmd）在「桌面应用」类型下会被拒绝，请改用「命令行」类型 ——
桌面类型是不带 shell 直接 spawn 的，本来就起不了批处理；命令行类型要经 `cmd.exe`
开终端，跑批处理反而没问题。

**3. 只在 Windows 上验证过。** 命令行类型「在新终端窗口里运行」这条路是 Windows 独有的：
开终端的方式各平台不同（macOS 要调 `Terminal.app`，Linux 得看装了哪个终端模拟器），
没有环境验证，所以**没有写**。非 Windows 上命令行类型维持直接 spawn 的老行为，
`claude`、`python -i` 这类交互式程序起不来（会静默退出）。桌面类型和其余功能不受影响。

## 安全设计

### 边界一：进程启动

核心是**参数不经过任何解析**，而不是字符串转义。桌面类型直接以数组交给 `spawn`；
命令行类型为了开出终端必须经 `cmd.exe`，没法再绕开解析，所以改成把会改变含义的参数
**挡在门外** —— 同样是「不解析」，只是手段从绕开变成了拒绝。

| 措施 | 作用 |
| --- | --- |
| `spawn` 全程 `shell: false` | 桌面类型参数以数组直传，路径里的 `&` `\|` 不会被解释 |
| 命令行类型拒绝 shell 元字符 | 它必须经 `cmd.exe` 的 `start` 才能开出终端，所以 `& \| ^ < > % "` 直接拒绝，不做转义 |
| 命令行类型先查 `PATH` | 经了 `cmd` 就收不到「命令没装」的错误，启动前自己解析一遍，解析不出来就报 `COMMAND_NOT_FOUND` |
| 命令允许列表 | 命令类型必须命中，默认 16 个，设置页可自行扩展 |
| 白名单存服务端 | 存在 `~/.ai-workbench/config.json`，不由前端随请求下发 |
| 拒绝 .bat/.cmd | 仅限桌面类型：`spawn` 不带 shell 起不了批处理，引导改用命令行类型 |
| 路径不落盘 | 后端不持久化任何 Agent 路径 |

### 边界二：浏览器跨站调用

本地服务绑在 `127.0.0.1`，但**浏览器里的任何网页同样能请求 localhost**，所以不止绑回环就完事。
三层措施**防的是浏览器跨站调用，不是身份认证**：

| 措施 | 作用 |
| --- | --- |
| `Origin` 白名单 | 跨站请求必定带 Origin，对不上直接 403 |
| 严格 CORS | 只列本地两个源，不用 `origin: true` |
| 强制 `X-AIWB` 请求头 | 触发预检，跨站表单发不出这个头 |

**这三层不构成完整的认证。** 它们挡的是「别的网站偷偷调你的本地接口」，
挡不住「本机上任意能发 HTTP 请求的程序」—— 任何本地进程都能伪造 `Origin` 和请求头。

当前架构下这没问题：前端由本地 Vite 提供，服务只监听回环，使用者就是本机用户本人。
但如果以后打包成桌面端、把本地 API 暴露给更多调用方，**需要补一个服务端生成的随机 token**：
启动时生成，通过受控的启动流程交给前端（例如注入到由服务端提供的那份 HTML 里，
跨站页面读不到别的源的 DOM）。**不要**把 token 写死在前端源码里，也不要放在前端可自由读取的公开配置里 ——
那等于没有。

### 边界三：模型凭据

| 措施 | 作用 |
| --- | --- |
| key 只存服务端 | 写在 `~/.ai-workbench/config.json`，接口只返回「配没配 + 头尾几位」，中间部分不出进程 |
| 前端拿不到 key | `GET /api/config/ai` 的响应做过多轮断言，确认不含完整 key；状态对象的**字段名走白名单**，新增字段必须先过测试那一关 |
| 供应商预设不含凭据 | 预设表是纯数据，没有 key 的位置；有一条测试扫描它，防止以后被写进去 |
| 进不去仓库 | `npm run hooks:install` 装一个 pre-commit 钩子，提交前扫暂存区；CI 里另有一道，防 `--no-verify` 绕过 |
| 端点不由环境变量决定 | 见下 |

端点地址不读环境变量。`ANTHROPIC_BASE_URL` 和 `ANTHROPIC_AUTH_TOKEN` 会被 SDK 默认读取，
而这个应用很可能从「已经为别的工具配了代理」的 shell 里启动，请求会发去第三方端点，
报错看不出原因。端点只认应用自己的配置，默认 `https://api.anthropic.com`，要代理在设置页填。

凭据本身仍可以用 `ANTHROPIC_API_KEY` 环境变量提供，换一把 key 不改变请求去向。

供应商预设也遵守同一条：预设是设置页的填充器，选中只是把值填进表单，存下来的是那份配置，
请求发去哪始终由配置决定。做成「选一下、代码里推导地址」的话，升级一次就可能把老用户的请求
改道。

### 已验证的用例

- 用其他 Origin 调 `/api/agent/launch`、`/api/data` → 403
- 缺 `X-AIWB` 头 → 403
- 桌面类型路径里带 `&` → `NOT_FOUND`，未执行任何东西
- `.bat` → `BATCH_NOT_SUPPORTED`，标记文件未被创建
- 命令行类型参数里带 `&` → `ARG_UNSAFE`，一个进程都没起
- 命令行类型命令没装 → `COMMAND_NOT_FOUND`
- 用旧 revision 写 `/api/data` → 409，拒绝覆盖
- 中文内容写入磁盘再读回 → 一致

以上除 403 两条外，其余都由 `npm run test:launch` 覆盖（30 项）。
